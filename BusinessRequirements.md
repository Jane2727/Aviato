# Документация по требованию «Дублирование объявлений (Сервис Draft)»

## 1. Бизнес требование: Дублирование объявлений

### Назначение проекта

Проект предназначен для создания инструмента быстрого копирования существующих объявлений.
Сервис Draft позволяет пользователям копировать структуру, текст и медиафайлы уже опубликованных объявлений для создания новых, что является важным инструментом для пользователей, размещающих объявления с однотипными товарами или услугами.

### Бизнес-цели

Снижение времени на создание новых объявлений (Time-to-Publish).
Увеличение общего объема публикуемых объявлений на платформе (рост LTV пользователей).
Повышение конверсии из зарегистрированного пользователя в активного продавца.
Увеличение выручки за счет предложения более дорогих или продвинутых функций при создании копий.

### Целевая аудитория

Малый бизнес, ИП, частные продавцы: предложения однотипных товаров.
Частные мастера: одинаковые услуги, где меняется только город.

## 2. Бизнес-процессы

### Основной процесс:

1. Пользователь открывает карточку своего объявления в статусе «Активно» (ACTIVE) или «В архиве» (ARCHIVED).
2. Нажимает кнопку «Создать копию».
3. Система создает Черновик (Draft) в сервисе Draft со статусом DRAFT, копируя данные и инициируя фоновое копирование медиа.
4. Пользователь перенаправляется на страницу редактирования Черновика.
5. Пользователь вносит изменения (опционально).
6. Нажимает «Сохранить изменения».
7. Система последовательно проверяет статус медиафайлов, актуальность категории и запускает валидацию анти-спама.
8. Если валидация пройдена, то черновик отправляется на модерацию.

### Вспомогательные процессы:

- Отмена создания:
  Пользователь нажимает кнопку «Отменить и выйти».
  Черновик помечается как удаленный, ресурсы освобождаются.

- Фоновая обработка медиа:
  Асинхронное копирование изображений и видео в объектное хранилище без повторного транскодинга (если видео уже обработано).

- Обработка неактивных категорий:
  Если категория оригинала удалена или деактивирована, то система позволяет создать черновик, но блокирует публикацию до выбора новой категории.

- Автоматическая очистка:
  Черновики старше 7 дней удаляются (с продлением TTL при любом обращении к черновику, как при чтении, так и при редактировании).

- Анти-спам валидация:
  При публикации проверяется наличие дублей.
  Если найдено 5 одинаковых объявлений, то публикация блокируется, а пользователь видит предупреждение о блокировке.

## 3. Функциональные требования

### Основной функционал

- Отображение новой кнопки «Создать копию» (доступна только владельцу, и только для объявлений в статусе ACTIVE или ARCHIVED): в зависимости от размеров экрана, кнопка будет показана либо отдельно, либо как пункт меню для действий с карточкой объявления
- Предзаполнение всех полей (категория, характеристики, описание, цена, адрес и.т.д), как в оригинальном объявлении.
- Перенос медиафайлов (фото и видео).
- Копирование видео без повторного транскодинга (если оригинал уже обработан).
- Присваивание статуса «Черновик» для нового объявления (до момента нажатия на кнопку «Сохранить изменения»).
- Кнопки «Сохранить изменения» (отправка на публикацию) и «Отменить и выйти» (удаление черновика).
- «Черновики» попадают во вкладку «Ждут действий» на странице «Мои объявления» в личном кабинете пользователя

### Дополнительный функционал

- Сброс промо-опций:
  При копировании все платные услуги (поднятие, выделение) сбрасываются.
  В UI отображается предупреждение: «Промо-опции не были скопированы. Вы можете добавить их заново перед публикацией».

- Анти-спам валидация при публикации:
  Если найдено 5 одинаковых активных объявлений (количество настраивается, по умолчанию 5), показывается предупреждение про необходимость изменения описания или фото, иначе будет применена блокировка до модерации.

- Обработка неактивных категорий:
  Если категория оригинала недоступна, то кнопка «Сохранить изменения» будет заблокирована, а пользователю будет показано предупреждение:
  «Категория исходного объявления больше недоступна. Выберите новую категорию».
  Кнопка «Сохранить изменения» будет заблокирована до выбора новой категории.

- TTL черновиков:
  7 дней с момента создания. TTL продлевается ещё на 7 дней при любом обращении к черновику (открытие страницы редактирования, чтение или сохранение изменений).

- Индикатор загрузки медиафайлов:
  Если копирование видео занимает время, на UI будет показан прогрессбар. Статус отображается по черновику в целом, без детализации по отдельным файлам.

## 4. Бизнес-метрики

### Ключевые показатели эффективности (KPI)

- Adoption Rate: процент пользователей, воспользовавшихся новой функцией хотя бы раз.
- Draft-to-Publish Conversion: процент успешно опубликованных объявлений из созданных черновиков.
- Time-to-Publish: среднее время создания объявления (для целевой аудитории оно должно снизиться).
- Retention Rate: удержание продавцов на платформе (сравнение продавцов с новой функцией и без).
- Upsell Conversion Rate: процент пользователей, добавивших промо-опции к скопированным объявлениям.

### Финансовые показатели

- Рост выручки от платных услуг (продвижение, выделение) за счет увеличения базы активных объявлений и применения промо-опций.
- Снижение стоимости привлечения лида (CPL) за счет органического роста контента.

## 5. Ограничения и зависимости

### Внешние зависимости

- Медиа-сервис (S3/CDN): доступность для копирования объектов.
- Сервис модерации: проверка дублей и отправка на модерацию.
- Сервис категорий: проверка актуальности правил категории при создании черновика и публикации.
- Анти-спам сервис: проверка на дубли при публикации.

### Внутренние ограничения

- Лимит на количество активных объявлений у пользователя (проверяется при публикации, а не при создании черновика).
- Лимит на размер медиафайлов: 10 фото и 1 видео (до 50 МБ) на объявление (если видео в оригинале было на границе лимита, а правила обновились).
- TTL черновиков: 7 дней (продлевается при любом обращении к черновику).
- Анти-спам лимит: настраиваемое количество одинаковых объявлений (по умолчанию 5) на одного пользователя в одной категории.
- Дублирование доступно только из объявлений в статусе ACTIVE или ARCHIVED (из DRAFT, MODERATION, DELETED и BANNED копирование запрещено).

## 6. Риски

### Технические риски

- Дублирование медиафайлов займет все место в S3 и увеличит затраты.
  Решение: Использовать серверное копирование объектов (S3 CopyObject) без скачивания на бэкенд. Внедрить TTL для неопубликованных черновиков (удаление через 7 дней).

- Долгая загрузка страницы редактирования из-за ожидания копирования видео.
  Решение: Асинхронное копирование. На UI показываем фото сразу, а для видео прогрессбар.

- Повторный транскодинг видео увеличит затраты на CPU/GPU.
  Решение: Копировать готовые файлы без повторного транскодинга (если оригинал уже обработан).

### Бизнес-риски

- Рост числа абсолютных дублей в приложении.
  Решение: Интеграция с анти-спам модулем и проверка при публикации. Если пользователь жмет «Сохранить» без изменений и есть несколько дублей, то система предупреждает или блокирует публикацию.

- Потеря дохода от промо-опций при копировании.
  Решение: Промо-опции не копируются. В UI показывается предупреждение с предложением добавить их заново.

### Операционные риски

- Риск: Пользователи не понимают, почему черновик исчез.
  Решение: Email/push-уведомления о скором удалении неактивных черновиков (за 1 день до истечения TTL).

- Риск: Пользователи не понимают, почему не могут опубликовать черновик из-за неактивной категории.
  Решение: Четкое предупреждение в UI с предложением выбрать новую категорию (в дальнейшем автоподбор похожих категорий на основе названия).

## 8. Успех проекта

### Критерии успеха

- Фича доступна 100% пользователям в рамках A/B теста.
- Отсутствие критических багов после релиза.
- Время создания объявления через копирование на 30% меньше, чем с нуля.
- Процент пользователей, добавивших промо-опции к скопированным объявлениям > 10%.

### Измеримость успеха

- Дашборд с отслеживанием воронки: Клик «Создать копию» -> Открытие формы -> Сохранение -> Публикация.
- Отслеживание конверсии промо-опций.

## 9. Дальнейшее развитие

### Планы расширения

- Массовое копирование из списка объявлений.
- Автоподбор похожих категорий на основе названия
- Шаблоны объявлений (сохранение черновика без привязки к существующему объявлению).

### Долгосрочные цели

- Интеграция с CRM для автоматического создания черновиков из внешних систем.

## 10. Use Cases

### UC-001: Создание и публикация копии объявления

Название: Дублирование объявления с последующей публикацией.

User Story: Как пользователь сервиса, я хочу скопировать свое старое объявление, чтобы быстро создать новое, не вводя данные вручную.

Участники: Пользователь, Frontend, Backend (Draft Service), Media Service, DB, Anti-Spam Service.

Предусловия: Пользователь авторизован, является владельцем исходного объявления, исходное объявление не удалено.

Ограничения: Исходное объявление должно быть в статусе «Активно» (ACTIVE) или «В архиве» (ARCHIVED). Дублирование из статусов DRAFT, MODERATION, DELETED и «Заблокировано за нарушения» (BANNED) запрещено.

Триггер: Пользователь нажимает кнопку «Создать копию».

#### Основной сценарий по шагам:

1. Пользователь нажимает кнопку «Создать копию».
2. Frontend отправляет запрос POST /api/v1/listings/{id}/duplicate.
3. Backend проверяет права, статус исходного объявления (ACTIVE/ARCHIVED) и создает запись в БД со статусом DRAFT, expires_at = NOW() + 7 days.
4. Backend ставит в очередь задачу на копирование медиафайлов (без повторного транскодинга).
5. Backend возвращает ID нового черновика (Draft ID).
6. Frontend перенаправляет пользователя на страницу редактирования Draft ID.
7. Frontend загружает данные черновика (этот запрос также продлевает TTL черновика). Если промо-опции были в оригинале, показывает тултип: «Промо-опции не были скопированы...».
8. Пользователь вносит правки (опционально). При любом обращении к черновику TTL продлевается на 7 дней.
9. Пользователь нажимает «Сохранить изменения».
10. Frontend отправляет PUT /api/v1/drafts/{draft_id}/publish.
11. Backend проверяет:
    11.1 Статус обработки медиа (media_status == READY).
    11.2 Актуальность категории (category.is_active == true).
    11.3 Анти-спам валидацию (наличие n дублей).
12. Если все проверки пройдены, то Backend меняет статус на MODERATION.
13. Система показывает успешное создание объявления, происходит редирект в личный кабинет.

#### Альтернативные сценарии по шагам:

- А1 (Отмена): На шаге 8 пользователь нажимает «Отменить и выйти». Frontend вызывает DELETE /api/v1/drafts/{draft_id}. Черновик удаляется, пользователь возвращается в список объявлений.
- А2 (Медиа еще не скопировались): На шаге 9 видео еще в статусе PROCESSING. При сохранении (шаг 9) система блокирует публикацию с сообщением: «Подождите, медиафайлы еще обрабатываются».
- А3 (Категория неактивна): На шаге 7 категория оригинала недоступна. В UI показывается предупреждение: «Категория исходного объявления больше не доступна. Выберите новую категорию». Кнопка «Сохранить изменения» заблокирована до выбора новой категории.
- А4 (Анти-спам валидация): На шаге 11 анти-спам сервис обнаружил N+ одинаковых объявлений. Система показывает предупреждение: «У вас уже есть похожие объявления. Измените описание/фото или удалите дубликаты перед публикацией».
  Пользователь может:
  - Изменить описание/фото и повторить публикацию.
  - Нажать «Все равно опубликовать» (объявление отправляется на модерацию).
  - Отменить публикацию.

Постусловия: Создано новое объявление в статусе MODERATION. Исходное объявление осталось без изменений.

## 11. Нефункциональные требования

### Производительность

- Название: Время отклика при инициации дублирования.
- Описание: Время от нажатия кнопки до перехода на страницу редактирования.
- Критерии измерения: Время ответа API для 95% запросов не превышает 500 мс.
- Условия измерения / тестирования: Нагрузка 1000 RPS, размер объявления до 10 фото и 1 видео (50 МБ).
- Инструменты: JMeter, Grafana, Prometheus.
- Приоритет: Высокий.
- Обоснование: Копирование медиа не должно блокировать UI. Физическое копирование должно идти асинхронно.
- Целевое значение: p95 < 500 мс.

### Надежность

- Название: Целостность медиафайлов.
- Описание: Удаление или редактирование оригинального объявления не должно влиять на скопированное.
- Критерии измерения: процент объявлений с нерабочими ссылками на медиа.
- Условия измерения / тестирования: Ручное тестирование + автотесты на удаление оригинала.
- Инструменты: Selenium, Postman.
- Приоритет: Критический.
- Обоснование: Пользователь не должен потерять загруженный контент.
- Целевое значение: 0% инцидентов.

### Безопасность

- Название: Разграничение доступа (Insecure Direct Object Reference IDOR).
- Описание: Пользователь не может скопировать объявление другого пользователя.
- Критерии измерения: Количество успешных попыток копирования "чужого" объявления.
- Условия измерения / тестирования: Пентест, API Fuzzing.
- Инструменты: OWASP ZAP.
- Приоритет: Критический.
- Обоснование: Защита персональных данных и интеллектуальной собственности.

### UX/UI

- Название: Прозрачность статуса черновика.
- Описание: Пользователь должен легко понимать статус черновика, оставшееся время до удаления, причины блокировки публикации.
- Критерии измерения: процент пользователей, успешно завершивших публикацию без повторных обращений в поддержку.
- Условия измерения / тестирования: UX-тестирование, анализ обращений в поддержку.
- Инструменты: Hotjar, UserTesting.
- Приоритет: Высокий.
- Обоснование: Снижение нагрузки на поддержку, повышение удовлетворенности пользователей.
