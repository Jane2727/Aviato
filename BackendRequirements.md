# Документация по требованию «Дублирование объявлений (Сервис Draft)»

## Backend логика

### Общий обзор

Сервис Draft отвечает за создание, хранение и публикацию черновиков.
Высокоуровневая логика: при запросе дублирования создается каркас объявления в БД, а тяжелая операция копирования медиа передается в async-воркер.
Анти-спам валидация запускается только при публикации.

### Входные данные

```
// Запрос на создание дубликата
interface DuplicateListingRequest {
	// UUID исходного объявления (Listing)
	source_listing_id: string;
	// UUID текущего пользователя (из JWT)
	user_id: string;
}

// Запрос на сохранение/публикацию черновика
interface PublishDraftRequest {
	// UUID черновика
	draft_id: string;
	// UUID текущего пользователя (из JWT)
	user_id: string;
	// Измененные поля (текст, цена, и т.д.)
	payload: ListingPayload;
	// Флаг для принудительной публикации (после анти-спам предупреждения)
	force_publish: boolean;
}

// Запрос на продление TTL черновика
interface ExtendDraftTTLRequest {
	// UUID черновика
	draft_id: string;
	// UUID текущего пользователя (из JWT)
	user_id: string;
}
```

### Валидации

- Структурные:
  - Проверка типов UUID, наличие обязательных полей в payload.
- Бизнес-валидации:
  - source_listing_id принадлежит user_id.
  - Исходное объявление (source_listing_id) находится в статусе ACTIVE или ARCHIVED (дублирование из DRAFT, MODERATION, DELETED или BANNED запрещено)
  - У пользователя не превышен лимит активных объявлений (проверяется при публикации).
  - Категория исходного объявления все еще активна в справочнике (проверяется при публикации).
  - Черновик не истек (expires_at > NOW()).
- Валидации предметной области:
  - Цена > 0.
  - Текст описания не содержит запрещенных символов/ссылок.
  - Анти-спам валидация при публикации (проверка на N+ дублей).

### Интеграции

- Внешние сервисы
  - Media Service / S3: Для физического копирования файлов (без повторного транскодинга).
  - Moderation Service: Для отправки черновика на проверку при публикации.
  - Anti-Spam Service: Для проверки на дубли при публикации.
  - Category Service: Для проверки актуальности категорий.
  - Notification Service: Для отправки email/push-уведомления за 1 день до истечения TTL черновика.

- БД
  - PostgreSQL: Хранение метаданных объявлений и черновиков.

- Кэш (Redis)
  - Хранение состояния media_status для быстрого опроса (polling) с фронтенда
  - Кэширование справочника категорий.
  - Хранение счетчиков для анти-спам валидации.

### Исключительные ситуации

- 400 Bad Request: Превышен лимит объявлений, невалидные данные в payload, категория неактивна, черновик истек, исходное объявление не в статусе ACTIVE/ARCHIVED (не доступно для копирования).
- 403 Forbidden: Попытка скопировать чужое объявление (IDOR).
- 404 Not Found: Исходное объявление или черновик не найдены.
- 409 Conflict: Нарушение идемпотентности, медиа еще обрабатываются, обнаружены дубли (анти-спам).
- 500 Internal Server Error: Ошибка БД, недоступность S3.

### Производительность

#### Оптимизации

- Использование S3 CopyObject (серверное копирование внутри AWS/Yandex Cloud).
- Копирование видео без повторного транскодинга (если оригинал уже обработан).
- Асинхронная обработка медиа.
- Batch-операции для продления TTL при массовом редактировании.

#### Ограничения

- Максимальный размер одного объявления: 10 фото, 1 видео 50 МБ.
- TTL черновиков: 7 дней (продлевается при любом запросе к черновику, включая GET).
- Анти-спам лимит: настраиваемое количество дублей (по умолчанию 5).

### API

1. Создание черновика (дубликата)
   Метод: POST /api/v1/listings/{source_listing_id}/duplicate
   Headers: Authorization: Bearer <token>, Idempotency-Key: <uuid>
   Response: 201 Created (см. 12.7.1)

2. Получение данных черновика (для предзаполнения формы)
   Метод: GET /api/v1/drafts/{draft_id}
   Response: 200 OK (возвращает все поля, включая статус обработки медиа, expires_at, флаг promo_options_copied).
   Примечание: каждый такой запрос продлевает expires_at черновика на 7 дней.

3. Обновление черновика (продление TTL)
   Метод: PUT /api/v1/drafts/{draft_id}
   Body: Измененные поля объявления.
   Response: 200 OK (возвращает новый expires_at).

4. Обновление и публикация черновика
   Метод: PUT /api/v1/drafts/{draft_id}/publish
   Body: Измененные поля объявления, force_publish: boolean.
   Response: 200 OK, статус всегда переводится в MODERATION (при успешном запросе), 400 Bad Request (категория неактивна), 409 Conflict (медиа обрабатываются или найдены дубли).

5. Отмена и удаление черновика
   Метод: DELETE /api/v1/drafts/{draft_id}
   Response: 204 No Content

6. Получение списка черновиков пользователя
   Метод: GET /api/v1/drafts
   Query params: page, limit, sort_by
   Response: 200 OK (возвращает список черновиков с expires_at, превью, статусом).

### Критерии приемки

#### AC-001: Успешное создание черновика

Как пользователь, я хочу нажать кнопку «Создать копию», чтобы система создала черновик с моими данными.
Критерии:
Кнопка «Создать копию» видна только владельцу и только для объявлений в статусе ACTIVE или ARCHIVED.
При клике создается запись в БД со статусом DRAFT, expires_at = NOW() + 7 days.
Пользователь перенаправляется на страницу редактирования.
Все текстовые поля и характеристики предзаполнены.
Промо-опции сброшены, показывается уведомление.

#### AC-002: Корректная обработка медиафайлов

Как пользователь, я хочу, чтобы фото и видео скопировались, чтобы я мог их использовать в новом объявлении.
Критерии:
Файлы физически скопированы в S3 (новые ключи).
Удаление исходного объявления не удаляет файлы черновика.
Порядок фото и статус «Главное фото» сохранены.
Видео копируется без повторного транскодинга (если оригинал уже обработан).

#### AC-003: Публикация черновика

Как пользователь, я хочу нажать кнопку «Сохранить изменения», чтобы объявление ушло на модерацию.
Критерии:
Статус меняется на MODERATION.
Если медиа еще не скопированы, публикация блокируется с понятным сообщением.
Если категория неактивна, публикация блокируется с предложением выбрать новую категорию.
Если найдены дубли (анти-спам), показывается предупреждение с возможностью изменения или принудительной публикации.
Промо-опции не копируются, пользователь может добавить их заново.

#### AC-004: Отмена создания

Как пользователь, я хочу нажать «Отменить и выйти», чтобы удалить черновик и вернуться в список.
Критерии:
Черновик помечается как DELETED, проставляется deleted_at.
Файлы в S3 помечаются на удаление (или удаляются сразу).
Происходит редирект на страницу «Ждут действий».

#### AC-005: Продление TTL при обращении к черновику

Как пользователь, я хочу, чтобы срок действия черновика продлевался при работе с ним, чтобы не потерять свои наработки.
Критерии:
При любом запросе к draft_id, как при чтении (GET), так и при редактировании (PUT), expires_at продлевается на 7 дней. Отдельного действия пользователя (нажатия кнопки «Сохранить черновик») не требуется.
Пользователь видит обновленную дату истечения в UI.

#### AC-006: Автоматическая очистка истекших черновиков

Как система, я хочу автоматически удалять черновики старше 7 дней, чтобы не засорять БД и S3.
Критерии:
Фоновый джоб раз в сутки удаляет черновики с expires_at < NOW() (soft delete, с фиксацией deleted_at).
Пользователь получает email/push-уведомление за 1 день до истечения TTL.
Медиафайлы удаляются из S3.
Hard delete записей происходит через 30 дней после deleted_at.
